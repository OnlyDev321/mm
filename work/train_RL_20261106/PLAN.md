# R1 계획: 가설 B의 RL 버전 (GRPO)

작성 2026-11-06. **초안 — 데이터 방향 확정, 학습 설정 미확정.** 학습 전에 고정하고, 결과를 본 뒤 기준·설정을 바꾸지 않는다. 동작 문제로 바꾸는 경우만 변경 기록에 남긴다.

## 1. 배경과 가설

가설 B를 SFT로 세 번 검증했고 모두 불통과였다.

| 모델 | 학습 응답 | 900문항 | 128문항 net_gain | 정답→오답 / 오답→정답 |
|---|---|---|---|---|
| M0 | 없음 | 600 | — | — |
| E1 | 교사 정리 풀이 | 527 | −3 | 147 / 74 |
| E2 | 답만 | 493 | −4 | 178 / 71 |
| E3 | 교사 사고 과정 + 정리 풀이 | 597 | +6 | 83 / 80 |

해석(추정): SFT는 교사 응답을 따라 하게 만들어 M0의 원래 풀이를 덮어쓴다. 그래서 정답→오답이 많고(하방 방어 실패),
E3는 교사의 "끝까지 검토하는 습관"만 배워 어려운 문항에서 사고 과정을 닫지 못했다(length 153, 그중 141건 미닫힘).

**가설 R1:** 목표는 가설 B와 같다 (M0가 길게 헤매다 잘리는 추론 문제). 방법만 바꿔, M0가 **자기 응답** 중
"끝까지 가서 맞힌 응답"을 강화하도록 RL(GRPO)로 학습하면, 기존 정답을 지키면서 length 128문항의 정답이 늘어난다.

- 근거: 교수님 첨언(RL 권장). MMFineReason 논문도 SFT 뒤 RL 단계를 둠 (4B MMMU 69.3 → 69.6).
- 이 방향은 E1~E3의 validation 결과를 보고 정했다. 그래서 개발 점검은 학습 풀 holdout으로만 하고, validation 900문항은 최종 평가에 한 번만 쓴다.

### 3-2. 처리 단계

1. **답 형식 분류·보상 함수 검증 (CPU)** — 완료 (`reports/STAGE1_REPORT.md`). M0 자동 채점 추출 555/555 일치.
2. **풀 구성 (CPU, 1-2단계)**: A 상한 적용, B·C 추출 → 정답·형식·이미지·길이 검사 → MMMU·MMMU-Pro 중복 검사 → 평가 프롬프트 변환 → 합친 풀 확정.
3. **M0 시험 샘플링 (GPU)**: 합친 풀에서 분야 비율대로 층화 무작위 100건(seed 3407), K = 4.
   - 시간·표적 비율 확인 후 전체 샘플링 K(4 / 8) 확정
4. **M0 전체 샘플링 (GPU)**: 문항별 정답 횟수, length 종료 횟수, 방향 전환 마커 수, 출력 토큰 기록
5. **그룹 분류 (CPU)**

   | 그룹 | 조건 | 역할 |
   |---|---|---|
   | 표적 | K회 중 1회 이상 정답 **그리고** 1회 이상 length 종료 또는 방향 전환 과다(마커 21회 이상) | 가설 B 대상. "끝낸 정답" 강화 |
   | 유지 | 표적이 아니고 1 ~ K−1회 정답 | 하방 방어 |
   | 제외 | 전부 정답 또는 전부 오답 (전부 정답이면서 마커 과다인 경우도 제외, 겹침 기록) | 학습 신호 없음 (GRPO 그룹 보상이 모두 같음) |

6. **학습 세트 구성**: 그룹 분류에서 **섞인 문항(표적 + 유지) 전부**를 쓴다. 비율은 맞추지 않고 결과대로 보고. 순서는 seed 3407로 섞음 (2026-11-06 확정, 7:3에서 변경).
   - 시험 샘플링에서 표적이 전체 300건 미만으로 추정되면 B 확대(RL split 범위 확대 또는 SFT split 같은 과목)를 사용자와 논의. 자동으로 늘리지 않는다

## 4. 보상

| 경우 | 보상 |
|---|---|
| 정상 종료 + 정답 | 1 |
| 정상 종료 + 오답 / 답 추출 실패 | 0 |
| length 종료 (잘림) | 0 |

- 답 추출은 평가 자동 채점과 같은 Qwen 규칙 + `Final Answer` 보완을 먼저 쓴다. Judge는 쓰지 않음.
- **보강 추출 (2026-11-06 추가)**: 위 규칙이 추출에 실패한 경우에만, 응답 끝부분의 명시적 최종 답 표기(`oxed{X}`, `Answer:`/`Final Answer:`/`答案：` 뒤 선택지 문자, 끝부분 굵은 선택지 문자, 선택지 내용 정확 일치)를 규칙으로 읽는다. 서로 다른 답이 둘 이상이면 추출 실패.
  - 이유: 시험 400응답 중 추출 실패 118건(29.5%)에 `Final Answer: oxed{B}` 같은 명확한 답이 다수였다. 평가에서는 Judge가 처리하지만 보상에서는 0점이 되어 정답 응답이 벌을 받고 형식만 학습된다.
  - 규칙은 학습 풀 시험 raw로 만들고 고정한 뒤, M0 MMMU Judge 경로 345건의 Judge 판정과 일치율로 한 번 검증한다 (채점기 확인 용도만, 규칙을 MMMU에 맞춰 고치지 않음).
- 형식 보상·길이 페널티는 넣지 않는다 (보상 해킹 위험). 잘림 0점만으로 "끝까지 가기"를 유도.

## 6. 파일럿 (본학습 전)
