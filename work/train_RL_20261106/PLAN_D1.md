# D1 계획: 가설 B의 선호 학습 버전 (DPO)

작성 2026-11-06. **β·rpo_alpha·lr·epoch 확정 (2026-11-06).** 학습 전에 고정하고, 결과를 본 뒤 기준·설정을 바꾸지 않는다. 동작 문제로 바꾸는 경우만 변경 기록에 남긴다.
데이터 준비(풀·보상·M0 샘플링)는 R1과 공유한다 → `PLAN.md` 3·4절.

## 1. 배경과 가설

- 가설 B를 SFT로 세 번 검증했고(E1·E2·E3) 모두 불통과. SFT는 교사 응답으로 M0의 풀이를 덮어써 정답→오답이 많았다.
- R1(GRPO)은 비용·구현 부담이 커서, 같은 데이터로 먼저 오프라인 선호 학습(DPO)을 한다. GRPO는 준비된 채 보류 (`HANDOFF_R1_stage4_pilot.md`).

**가설 D1:** M0 자신의 응답 중 "끝까지 가서 맞힌 응답"을 "헤매다 잘리거나 틀린 응답"보다 선호하도록 DPO로 학습하면,
기존 정답을 지키면서 M0 length 128문항의 정답이 늘어난다.

- 근거: 강의 자료 p17 (DPO 등 선호 목적함수). 응답이 모두 M0 자신의 것이라 SFT처럼 남의 문체로 덮어쓰지 않는다.

## 2. 비교

| 모델 | 학습 | 비교 목적 |
|---|---|---|
| M0 | 없음 | 판정 기준 (기존 600/900) |
| E1·E2·E3 | 가설 B SFT (기존 결과) | 기술 비교 |
| **D1** | M0에서 시작한 DPO | D1 vs M0: 판정 |

## 3. 데이터 (선호 쌍)

| 항목 | 값 |
|---|---|
| 원천 | R1 3단계 M0 전체 샘플링 (1,500문항 × K=4, `reward_v2`) 중 학습 세트 `runs/full_k4/r1_train.jsonl` (섞인 문항 = 표적 + 유지) |
| chosen | 같은 문항의 응답 중 **정상 종료 + 보상 1** (`correct` 또는 `fallback_correct`) |
| rejected | 같은 문항의 응답 중 보상 0. 우선순위: ① **잘림(`length`)** → ② 정상 종료 오답(`wrong`/`fallback_wrong`) → ③ 추출 실패 |
| 문항당 쌍 수 | 최대 2쌍 (chosen·rejected 각각 중복 없이). 가능한 쌍이 1개면 1쌍 |
| 선택 순서 | 위 우선순위 안에서 `random.Random(3407)` |
| 입력 | 샘플링 때와 같은 프롬프트·이미지 (평가 형식). 정답은 입력에 넣지 않음 |
| 잘린 응답 | 생성된 그대로 (EOS 없음). 자르거나 고치지 않음 |
| 개발용 | 별도 분할 없음. 학습 지표(reward margin, chosen/rejected logp)만 관찰, 체크포인트 선택에 쓰지 않음 |

- 규모(3단계 결과로 계산): 548문항 → **707쌍** (2쌍 159문항, 1쌍 389문항). rejected 종류: 정상 종료 오답 475 / 잘림 190 / 추출 실패 42. 1 epoch ≈ 44 step
- 표적 문항에서는 주로 "끝맺은 정답 vs 잘린 응답", 유지 문항에서는 "정답 vs 오답" 쌍이 된다.

## 4. 학습 설정

| 항목 | 값 |
|---|---|
| 시작 모델 | M0 (`Qwen/Qwen3-VL-4B-Instruct`, revision `ebb281ec…`) |
| 도구 | ms-swift 3.12.3 `rlhf_type dpo` |
| LoRA | E1과 같음: r 16, α 32, dropout 0.05, LM 36층 q/k/v/o/gate/up/down. ViT·merger 고정 |
| 기준 모델 | M0 (LoRA adapter를 끈 모델) |
| loss | sigmoid DPO, β **0.1** |
| rpo_alpha | **1.0** — chosen에 SFT loss를 더해 chosen 확률이 떨어지는 DPO 고질 문제 방지. 0이면 순수 DPO |
| 최적화 | lr **5e-6**, cosine, warmup 3%, batch 1 × 16, seed 3407 |
| epoch | **2** — 쌍 수가 적어 1 epoch는 약 44 step. 학습 결과로 바꾸지 않음 |
| max_length | 쌍 중 최장 (프롬프트 + 응답) 이상, 12,288 이하에서 고정. 초과하면 멈추고 보고 |
| 체크포인트 | 마지막만 사용 |
| GPU | A100/H100 80GB 1장 (잘린 응답 8,192토큰 + 프롬프트, chosen·rejected·기준 모델 계산) |

## 5. 파일럿

1. CPU: 쌍 5개 이상의 토큰 수(프롬프트·chosen·rejected)를 독립 계산과 ms-swift 전처리로 대조. 프롬프트가 평가 경로와 같은지
2. GPU 20 step: loss·reward margin·chosen/rejected logp 추이, 최장 쌍 포함 step까지 OOM 없음, 최대 VRAM, step 시간
3. 병합 → vLLM 0.11.0 로딩
4. 본학습 시간·비용 견적 → 사용자 확인

## 6. 평가·판정

평가는 `work/eval_B_20261101/PLAN.md` 2절 조건 그대로 (900문항, v2 채점 + Judge). 판정은 R1과 같다 (`PLAN.md` 8절).

| 구분 | 기준 |
|---|---|
| 1차 | M0 length 128문항 net_gain ≥ **14** (k0 = 10). 참고로 ≥18 여부 |
| 안전 | 900문항 정확도 하락 ≤ 1.7%p, 그리고 정답→오답 ≤ 오답→정답 |
| 메커니즘 | length 종료 수 < 128, 방향 전환 과다율 < M0(24.1%) |

- 처리 경로(자동/Judge) 변화를 따로 보고한다. 보상이 규칙 추출 형식을 선호하므로 자동 채점 비율이 늘 수 있고, 이를 실력 향상으로 해석하지 않는다.

## 7. 지키는 것

- MMMU / MMMU-Pro는 학습에 쓰지 않는다.
