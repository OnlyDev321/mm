# R1 2-2단계 보상 추출 보강 검증

**2-2단계 완료.** 첫 검증에서 중단한 뒤, 승인된 동작 오류를 수정하고 새 해시로 재검증했다. 시험 재채점·그룹 재분류와 샘플러 옵션 추가까지 완료했다. 최초 기록은 아래에 보존했고 최종 결과는 [재개 기록](#재개-기록)에서 확인할 수 있다.

## 최초 검증 기록

학습 풀 시험에서 명시적 답을 오추출한 건은 없었다. MMMU에서는 보강 추출에 성공한 183건 모두 보관된 Judge와 일치했다. 다만 `A. A`처럼 선택지 내용 자체가 한 글자인 명시적 답을 복수 선택으로 거르는 오류가 6건에서 반복됐다. 이 중 3건은 Judge 정답이 0점으로 남았다. 지침의 체계적 오류 중단 조건에 따라 당시에는 3절 재채점·그룹 재분류와 4절 샘플러 적용을 보류했다.

최종 표기 주분류는 한 응답당 하나다. 답 선언을 반복하거나 표기를 섞은 경우가 있었다. 예를 들어 #44는 최종 문자 선언 앞에 선택지 내용만 별도로 썼고, #73은 최종 결론 앞에 내용만 박스로 표시했다. 추론 중 번복이나 대안 재검토를 표시한 응답은 29건으로, 최종 복수 선택과 구분했다. #11은 보기 중 유효한 선택이 없다고 결론 내렸다.

고정한 `scripts/reward_v2.py`의 SHA-256은 `96704f5436ebbe8a6d4f9455d1d123da7d6d56ae0379e1262add9957c116664f`다. 코드·시험 raw·수기 판독의 해시를 `reward_v2_freeze.json`에 기록한 다음 검증했다.

1. 기존 `reward.py`를 먼저 호출한다. 객관식(`mc_letter`, `mc_value`)에서 기존 결과가 `extract_fail`일 때만 보강한다. `length`는 기존과 같이 0점이다.
2. 응답 끝 공백을 제외한 마지막 512문자에서 온전한 줄만 읽는다. 구분선과 독립된 수식 구분자를 건너뛰고, 마지막에 정해진 형태의 짧은 주석이 한 줄 붙은 경우만 그 앞줄을 종단으로 삼는다. 주석 상한은 정규화 후 210문자다.
3. 답 머리말이 있는 줄을 우선 읽는다. 머리말만 있으면 바로 다음 유효 줄을 읽는다. 종단에 연속된 박스나 굵은 선택지 줄도 읽는다. 후보 안에서는 박스 및 표시용 감싸기를 벗긴 뒤 선택지 문자를 우선 확인하고, 문자가 없으면 NFC·공백·표시용 감싸기를 정규화한 선택지 내용 전체가 유일하게 일치하는지 확인한다.
4. 종단의 유효 답이 필요하고, 범위 안에서 추출된 다른 명시 답도 모두 그 문자와 같아야 한다. 인식한 복수 답, 유효하지 않은 선택지 문자 또는 중복 선택지 내용은 실패 처리한다. 성공 시 `fallback_correct` 또는 `fallback_wrong`으로 기록한다.

## 3–5. 중단 이후 상태

- 재채점 raw와 새 그룹 결과를 만들지 않았다. 기존 표적 25 / 유지 26 / 제외 49와 당시 단순 외삽 375 / 390은 참고용 기존 값이다. 새 그룹·분야·출처별 건수와 1,500건 새 외삽은 산출하지 않았다.
- 전체 샘플러 옵션과 GRPO 연결은 적용하지 않았다. `sample_m0.py`, `build_groups.py`, 그룹 기준, 7:3, 풀 구성을 유지했다.
- CPU에서 기존 Python 환경만 사용했다. GPU·파드·유료 API 호출·패키지 설치·GitHub/HF 업로드는 없었다.

### 전체 샘플링 옵션과 GRPO 인터페이스

- `sample_m0.py --run --reward-v2`로 고정 보강 보상을 선택한다. 생략하면 기존 보상을 사용한다. 옵션 사용 시 해시를 검사하고 run manifest에 보강과 기존 보상 코드의 해시를 각각 기록한다. 실행 중에는 응답 원문과 보상 숫자·이유를 기존 raw 필드에 기록한다.
- `--help`, 두 보상 선택 경로, manifest 필드, 잘림 0점을 CPU에서 확인했다. 샘플러 파일 자체의 해시도 기존 resume 검증에 포함되므로, 이전 샘플러로 만든 run 디렉터리에는 새 코드가 이어 쓰지 않는다. 전체 샘플링에는 새 출력 디렉터리를 사용한다.
- GRPO에서는 같은 `reward_v2.reward(response: str, finish_reason: str, item: dict) -> tuple[int, str]`를 사용한다. `response`는 잘라내지 않은 응답 원문이며 `finish_reason`은 생성기가 반환한 `stop` 또는 `length`다. `item`은 학습 풀의 `format`, `answer`, `choices`를 그대로 전달한다. 배치에서는 각 응답에 그 문항의 메타데이터를 맞추고 반환한 0/1만 학습기에 넘긴다. 이유 문자열은 로그용으로 남긴다. GRPO 연결 코드는 이 단계 범위 밖이다.
