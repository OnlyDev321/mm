# E3 계획: 사고 과정 포함 SFT (가설 B 후속)

작성 2026-11-01. 학습 전에 고정한다. 결과를 본 뒤 기준·설정을 바꾸지 않는다. 동작 문제로 바꾸는 경우만 변경 기록에 남긴다.
상태: **확정 (2026-11-01, `<think>` 태그 유지). 팀에는 공유**

## 1. 배경과 가설

가설 B(E1 정리 풀이, E2 답만)는 둘 다 불통과였다 (E1 527/900, E2 493/900, M0 600/900).
length 종료·방향 전환 과다는 크게 줄었지만 정확도가 함께 떨어졌다.
해석(추정): 정리 풀이는 교사가 사고 과정으로 답을 찾은 **뒤의 요약**이라, 4B 모델이 탐색·검토 없이 확신형 풀이를 따라 하게 됐다.

**가설 E3:** 같은 문항에서 교사의 사고 과정까지 함께 학습하면, E1에서 잃은 탐색·검토가 유지되어 M0보다 정확도가 오른다.
참고: MMFineReason 논문은 사고 과정 전체 SFT로 4B MMMU 67.4 → 69.3.

## 2. 비교

| 모델 | 학습 | 비교 목적 |
|---|---|---|
| M0 | 없음 | 판정 기준 (기존 600/900, 재실행 안 함) |
| E1 | 정리 풀이 + Final Answer (기존 결과 재사용) | E3 vs E1: 사고 과정 유무 효과 (기술 보고) |
| **E3** | 사고 과정 + 정리 풀이 + Final Answer | E3 vs M0: 판정 |

E1과 E3는 문항·이미지·프롬프트·학습 설정이 같고 **응답에 사고 과정이 있는지만** 다르다.

## 3. 데이터

| 항목 | 값 |
|---|---|
| 문항 | E1과 같은 3,000건, 같은 순서 (HF `MMDL-team4/hypB-train-data` v1.1 목록) |
| 입력 | E1과 동일 (이미지 앞배치, 평가 프롬프트, min/max_pixels) |
| 응답 | MMFR `qwen3vl_235b_thinking_response`의 `<think>사고 과정</think>`(원문 그대로) + **E1 응답 그대로**(정리 풀이, 답 태그를 `Final Answer: X`로 바꾼 것) |

## 4. 학습 설정

E1과 같고 **max_length만 8,192 → 10,240**.
E1·E2의 최대 시퀀스는 4,906이라 E1을 10,240으로 학습해도 결과가 같았다 → E1과의 비교 조건은 유지된다.

| 항목 | 값 |
|---|---|
| 모델 | `Qwen/Qwen3-VL-4B-Instruct`, revision `ebb281ec…` |
| 도구 | ms-swift 3.12.3 |
| LoRA | r 16, α 32, dropout 0.05, LM 36층 q/k/v/o/gate/up/down (252 모듈). ViT·merger 고정 |
| 최적화 | lr 1e-4, cosine, warmup 3%, 1 epoch, batch 1 × 16 = 188 step, seed 3407 |
| max_length | **10,240** |
| loss | 응답 전체(사고 과정 포함). 프롬프트·이미지는 마스킹 |
| 체크포인트 | 마지막만 사용. holdout loss로 고르지 않음 |

GPU: 48GB급(RTX 6000 Ada / L40S) 우선. 파일럿에서 OOM이면 80GB(A100/H100)로 바꾸고 설정은 그대로.
예상 시간: 학습 토큰이 E1의 약 1.9배 → E1 56분 기준 약 2시간 안팎 (파일럿 step 시간으로 확정).

## 5. 파일럿 (본학습 전)

1. CPU: E3 기준값(전체·이미지·프롬프트·응답 토큰 수)을 행 0, 1, 2, 1161, 2298에 대해 만들고 ms-swift 전처리 결과와 정확히 일치하는지 확인. `<think>`·`</think>`가 특수 토큰으로 한 개씩 인코딩되는지, 응답 시작 경계(E1의 +1 사례)도 확인
2. GPU 20 step: loss 정상 감소, 마스킹 정상, **행 2298이 들어간 step까지 OOM 없음**, 최대 VRAM·step 시간 기록
3. 병합 → vLLM 0.11.0 로딩 확인
4. 하나라도 실패하면 본학습 하지 않고 보고

## 7. 판정 기준 (학습 전 고정)

| 구분 | 기준 |
|---|---|
| 1차 | M0 length 128문항 net_gain ≥ k0 + 4 = **14** (k0 = 10, seed 변경 재실행 최댓값). 참고로 k0=14(≥18) 통과 여부도 기록 |
| 안전 | 900문항 정확도 하락 ≤ 1.7%p, 그리고 정답→오답 ≤ 오답→정답 |
| 메커니즘 | length 종료 수가 M0(128)를 넘지 않는가. 방향 전환 과다율은 E3에서 늘 수 있으므로 판정 없이 보고 |

- 모든 기준은 v2(Judge 포함) 점수. Judge 없는 점수는 참고만.
- E3 vs E1(정확도, 오답→정답 / 정답→오답, 분야별)은 사고 과정 효과로 기술 보고하며 판정에 쓰지 않는다.
- 추가로 보고: 출력 토큰(평균·중앙값), 처리 경로, 반복 후보율, 분야·과목별 정확도.
